1. Data, Data Types & Data Structures — The Basics

1.1 What is Data?

Every application reads data, processes it, stores it temporarily, and produces output data. Data is simply a collection of raw facts — numbers, characters, etc. — that a program works on.

Flow of a Program

Data (input) → Application Program (processing) → Data (output)

1.2 Data Type

Data is classified into data types such as int, char, float, etc. A data type is defined by two things:

  1. A domain — the set of allowed values the data type can hold.
  2. A set of operations — the valid operations that can be performed on those values.

If a program performs a wrong/illegal operation on a data type, the compiler raises an error. Example: char x, y, z; z = x * y; is invalid because multiplication is not a defined operation on char.

Data TypeDomainOperations
boolean0, 1AND, OR, =, etc.
charASCII set=, <>, <, etc.
integer-maxint to +maxint+, -, =, ==, <>, <, etc.

1.3 Built-in vs User-defined Types

1.4 Simple (Atomic) vs Structured Data Types

Simple / Atomic Data Types

Have no component parts — they cannot be broken down further. Example: int, char, float — e.g. 18, 2.5, 'x'.

Structured Data Types

Can be broken down into component parts (fields). Example: an object, array, set, file.

Example — Student record: A student object has components Name, Age, and Branch — each a separate "component part" of the whole structure.

When elements of structured data are organized, four fundamental shapes are commonly used:

GraphElements (nodes) connected by edges with no strict hierarchy.

2. Elementary Data Organization

Before data can be structured into arrays, lists, trees etc., we must understand the basic "building block" terminology used to describe how raw data is organized into meaningful units.

TermMeaning
DataCollection of raw, unprocessed facts and figures (numbers, characters, symbols).
Data ItemA single unit of value. Divided into Group Items (can be divided further, e.g. "Date" → day, month, year) and Elementary Items (cannot be divided further, e.g. a single digit).
EntitySomething that has certain attributes/properties which may be assigned values. E.g., "Student" is an entity.

Memory Hook

Data Item → Entity → Attribute (Field) → Record → File — exactly how a database table is built: a file is made of records (rows), and each record is made of fields (columns).

3. Data Structure — Definition & Representation

Definitions (any one is exam-ready)

1. A data structure is a way of storing and organizing data in a computer so it can be used efficiently.

2. When elements of data are organized together in terms of some relationship among the elements, the organization is called a data structure.

3. A data structure is a scheme for organizing data in computer memory.

4. A data structure is a set of data values together with the relationships between them and the set of operations permitted to be performed on them.

3.1 Why Data Structures Matter

The way data is organized directly affects the performance of a program. Programmers pick a data structure based on the nature of the data and what operations need to be done efficiently on it.

3.2 Example — Choosing between a Queue and a Binary Tree

4. Classification of Data Structures

4.1 Based on Organization: Linear vs Non-Linear

Linear Data Structure

Data elements are arranged sequentially; each element is connected to its previous and next element. This lets you traverse the whole structure in a single run/level. Easy to implement since computer memory itself is sequential.

Examples: Array, Stack, Queue, Linked List.

Non-Linear Data Structure

Elements do not follow a single sequence; each element may connect to multiple other elements (multi-level storage). Harder to implement, but often uses memory more efficiently.

Examples: Tree, Graph, Hash Table, Heap.

5. Abstract Data Types (ADT)

5.1 What is Abstraction?

Abstraction means hiding implementation details and showing only the essential features to the user. Example: an integer like 243 is internally represented as 2×10² + 4×10¹ + 3×10⁰, but we never need to think about this while using it.

Definition — Abstract Data Type (ADT)

An ADT is a simple or structured data type whose implementation details are hidden from the user. It is a mathematical model along with a collection of operations defined on that model. The internal representation is encapsulated and not visible to users of the ADT.

5.2 Two Key Questions While Designing an ADT

QuestionAnswered by
WHAT values are in the domain? WHAT operations can be performed?Specification (written first)
HOW is the data type represented? HOW are operations implemented?Implementation (written after specification)

5.3 Users vs Implementers

A user of an ADT only needs to know the specification (what it does) — never the implementation details. An implementer must know specification + representation + implementation (how it is built).

Diagram: ADT Design Flow

Elements + Structure → Domain + Operations → Specification (user-visible) → Representation → Implementation (implementer-only)

5.4 ADT in Programming Languages

An ADT is an abstract model of a data structure together with the operations (algorithms) that process it. In C++ / Java, an ADT is typically implemented as a class; in C, it is typically implemented using a struct plus a set of functions that operate on it.

Exam-ready Answer: Define ADT

"An Abstract Data Type (ADT) is a mathematical/logical model of a data structure defined purely by its behaviour — i.e., the set of values it can hold and the set of operations that can be performed on it — without specifying how these are implemented internally. The implementation details are hidden from the user (encapsulation); only the specification is exposed. Example: a Stack ADT defines operations push(), pop(), peek(), isEmpty() without saying whether it is implemented using an array or a linked list."

Why these operations matter

Almost the entire DSA course is about implementing these six operations efficiently (in less time and/or space) for different data structures. That is exactly why we need algorithm analysis — covered next.

7. Algorithm — Definition & Characteristics

Definition

An algorithm is a finite sequence of well-defined, unambiguous instructions that, when followed, accomplish a particular task or solve a computational problem.

Optimality (desirable)Among all correct algorithms, a good one minimizes resource usage (time & memory).Efficiency in practice.

Step 1: Initialize max = first element
Step 2: For each element in the list
            If element > max
                Update max = element
Step 3: Return max

Exam-ready Answer: What is an Algorithm?

"An algorithm is a finite, well-defined, step-by-step procedure for solving a computational problem. It must have zero or more inputs, at least one output, and must be unambiguous, finite, effective, and general enough to work on all valid inputs of the problem, independent of any programming language."

8. Analysis of an Algorithm

8.1 Why Analyze Algorithms?

  • To determine resource usage — mainly time and space.
  • To select the most optimal algorithm among several alternatives that solve the same problem.
  • Necessary for performance-critical applications (e.g., real-time systems).

Performance analysis = estimating the time and memory requirement of an algorithm. Time estimation → time complexity analysis. Memory estimation → space complexity analysis. Since memory today is cheap & abundant, analysis usually defaults to time complexity.

8.2 Space Complexity

Definition

Space complexity is the amount of memory space required by an algorithm during its execution.

Reasons we study space complexity:

  • On multi-user systems, we may need to specify how much memory to allocate to a program.
  • We may want to know in advance if sufficient memory is even available to run the program.
  • There may be several solutions to the same problem with different memory requirements.

Components of Space used by a Program

ComponentDescription
Instruction SpaceSpace to store the compiled/executable code. This is fixed.
Data SpaceSpace to store all constants and variable values used.
Environment SpaceSpace to store information needed to resume suspended functions (e.g., recursion stack).

8.3 Time Complexity

Definition

Time complexity is the amount of time an algorithm needs to run to completion, expressed as a function of the input size n.

Reasons we study time complexity:

  • We may want to know in advance whether a program gives a satisfactory real-time response.
  • There may be multiple solutions with different time requirements — we pick the fastest.

8.4 Best Case, Worst Case & Average Case

The time taken by an algorithm can depend heavily on the actual input data, not just its size. So we define three cases:

CaseMeaningUsed When
Best CaseMinimum time taken, for the input most "suited" to the algorithm.Rarely useful alone — gives an overly optimistic picture.
Worst CaseMaximum time taken, over any input of size n. Gives an upper bound / absolute guarantee on running time.Most commonly used — guarantees the algorithm will never be slower than this.
Average CaseExpected time, averaged over all possible inputs of size n (needs probability theory).Useful if a certain input pattern repeats often in practice.

Worst case vs Average case

Worst-case complexity provides an absolute guarantee for how long a program will run — it is the longest possible time for any input of size n. Average-case complexity is suitable when a particular pattern of input repeats often, or when occasionally running slow is acceptable. Average-case analysis usually requires probability theory, so worst-case is far more commonly reported.

CaseScenarioComparisons

Worst CaseValue is the last element, or not present at alln

9. Time–Space Trade-off

Definition

The Time–Space Trade-off is a fundamental concept describing the relationship between an algorithm's execution time and its memory usage: it is a technique in which we increase memory usage to reduce execution time, OR reduce memory usage at the cost of increased execution time.

An algorithm can often be made faster by using more memory (e.g., pre-computed lookup tables, hash tables), or made to use less memory by doing more computation each time (recomputing instead of storing). A single problem may have several correct implementations that differ purely in this trade-off.

9.1 Real-life Analogy

Remembering 100 phone numbers:

Method 1: Memorize nothing; look up each number in a directory every time → takes more time, uses less memory.

Method 2: Store all numbers in your phone's contact list → uses memory, but gives instant (quick) access.

9.2 Factors Guiding the Choice

  • Available memory
  • Required execution speed
  • Input size
  • Frequency of the operation
  • Hardware constraints
  • Application requirements

9.3 Why It Matters

Real systems have limited resources. An algorithm that is fast but uses excessive memory may not fit a memory-constrained device; an algorithm that uses very little memory but is too slow may fail in a real-time application. The designer must balance:

  • Reducing execution time
  • Optimizing memory utilization
  • Improving overall system performance
  • Choosing the right data structure for the job

9.4 Practical Example — Searching a Roll Number Repeatedly

ApproachTimeAdditional Space
Linear SearchO(n) per searchO(1)
Hash TableAverage O(1) per searchO(n)
Sorted Array + Binary SearchO(log n) per searchDepends on storage (sorting cost)

Notice: the hash table trades extra memory for much faster average search time — a classic time–space trade-off.

Exam-ready Answer: Explain Time–Space Trade-off

"Time–space trade-off is a principle in algorithm design stating that the running time of an algorithm can often be reduced by using additional memory, and conversely, memory usage can be reduced by performing extra computation (increasing time). Since real systems have limited memory and require fast responses, algorithm designers must balance these two resources based on the application's needs, hardware constraints, and how frequently an operation is performed. Example: storing pre-computed results (more memory, less time) vs recomputing them every time (less memory, more time)."

10. Asymptotic Notations

10.1 Why We Need Them

The order of growth of an algorithm's running time gives a simple way to characterise its efficiency and compare it with alternatives. For large enough inputs, the multiplicative constants and lower-order terms of the exact running time become insignificant — only the highest-order term matters. So we describe running time using asymptotic notation, which captures how the running time grows as input size n → ∞, ignoring constants and lower-order terms.

What is Asymptotic Analysis?

Studying how the running time of an algorithm increases with the input size in the limit, as the input size grows without bound — focusing purely on the rate of growth, not exact step counts.

There are five standard notations: O (Big-Oh), Ω (Big-Omega), Θ (Big-Theta), o (little-oh), and ω (little-omega). Each describes a different rate-of-growth relationship between a function f(n) (actual running time) and a reference function g(n).

10.2 Big-O Notation — Upper Bound Worst Case

Formal Definition

O(g(n)) = { f(n) : there exist positive constants c and n₀ such that 0 ≤ f(n) ≤ c·g(n) for all n ≥ n₀ }

Meaning: g(n) is an asymptotic upper bound for f(n) — f(n) grows no faster than g(n) (within a constant factor), for large n. Intuitively: the set of all functions whose growth rate is the same as or lower than g(n).

Big-O gives the worst-case complexity of an algorithm — it is the most commonly used notation.

📊 Diagram — Big-O (visual idea)

Imagine plotting f(n) and c·g(n) on a graph. Beyond some point n₀, the curve of f(n) always stays below or touching c·g(n). That region below the line is the "O(g(n))" zone.

      c·g(n)  ______________↗
                        ____/
      f(n)      _______/
            ____/
      ______/
      ───────────┼──────────────────► n
                 n₀
✏️ Worked Example 1 — Any linear function an+b is O(n²)

We need c, n₀ such that an + b ≤ c·n² for all n ≥ n₀. Since for n ≥ 1, an + b ≤ (a+b)n ≤ (a+b)n², choosing c = a+b and n₀ = 1 works. Hence an+b = O(n²).

✏️ Worked Example 2 — Show 3n³ = O(n⁴)

We need 3n³ ≤ c·n⁴ for n ≥ n₀. Dividing both sides by n³ (n>0): 3 ≤ c·n. Choosing c = 1, we need n ≥ 3. So n₀ = 3, c = 1 works → 3n³ = O(n⁴).

✏️ Worked Example 3 — Show 5n³+15n²+7n+36 = O(n³)

Highest-order term is 5n³. Take c = 6: Need 15n²+7n+36 ≤ n³ for large n. At n = 10: LHS = 1500+70+36 = 1606; n³ = 1000 → false. Try bigger n: at n = 20, LHS = 6000+140+36=6176; n³=8000 → true. So with careful choice (say n₀ = 20, c = 6) the inequality holds for all n ≥ n₀. Hence the function is O(n³). (Also O(n⁴), O(n⁵)... since any higher power also upper-bounds it — but we always quote the tightest bound.)

Common Misunderstanding

The statement "f(n) = O(g(n))" does not mean equality — the "=" is really "∈" (belongs to a set). It means f(n) is a member of the set of functions bounded above by constant multiples of g(n). So it is perfectly valid (though unusual) to also write 3n³+5n²-9 = O(n⁴), n³ = O(3n³+5n²-9), even sin(x) = O(x⁴). In practice we always quote only the most dominant (tightest) term, e.g. "running time is O(n².⁵)".

10.3 Big-Omega (Ω) Notation — Lower Bound Best Case

Formal Definition

Ω(g(n)) = { f(n) : there exist positive constants c and n₀ such that 0 ≤ c·g(n) ≤ f(n) for all n ≥ n₀ }

Meaning: g(n) is an asymptotic lower bound for f(n) — f(n) grows at least as fast as g(n). Intuitively: set of all functions whose growth rate is the same as or higher than g(n). Ω gives the best-case complexity of an algorithm.

Example: Since the highest-order term of 5n³+15n²+7n+36 grows at least as fast as n³, this function is Ω(n³). It is also Ω(n²) and Ω(n).

✏️ Worked Example — Show √n = Ω(log n)

We need c, n₀ such that c·log n ≤ √n for n ≥ n₀. Since √n grows faster than log n for large n, choosing c = 1 and testing values (e.g. n₀ = 16: log₂16 = 4, √16 = 4 → equal; for n > 16, √n grows faster), the inequality holds. So √n = Ω(log n).

10.4 Big-Theta (Θ) Notation — Tight Bound Average/Exact

Formal Definition

Θ(g(n)) = { f(n) : there exist positive constants c₁, c₂, and n₀ such that 0 ≤ c₁·g(n) ≤ f(n) ≤ c₂·g(n) for all n ≥ n₀ }

Meaning: g(n) is an asymptotically tight bound for f(n) — the function is "sandwiched" between c₁g(n) and c₂g(n). Intuitively: the set of all functions with exactly the same rate of growth as g(n).

Theorem (very important for exams)

For any two functions f(n) and g(n):
f(n) = Θ(g(n))   if and only if   f(n) = O(g(n)) AND f(n) = Ω(g(n))

i.e. Θ(g(n)) = O(g(n)) ∩ Ω(g(n)). In practice, a tight bound is obtained by proving both the upper and lower bounds separately.

✏️ Worked Example — Show 10n²-3n = Θ(n²)

Upper bound: 10n²-3n ≤ 10n² trivially (since -3n < 0) → so c₂ = 10 works for all n.

Lower bound: Need c₁n² ≤ 10n²-3n ⟹ (10-c₁)n ≥ 3. Take c₁ = 9: need n ≥ 3.

So with c₁=9, c₂=10, n₀=3: 9n² ≤ 10n²-3n ≤ 10n² holds for all n ≥ 3. Hence 10n²-3n = Θ(n²). (Rule of thumb: make c₁ slightly smaller and c₂ slightly larger than the leading coefficient.)

10.5 Little-o Notation — Loose Upper Bound

Formal Definition

o(g(n)) = { f(n) : for all positive constants c, there exists a positive constant n₀ such that 0 ≤ f(n) < c·g(n) for all n ≥ n₀ }

Unlike Big-O, little-o describes a bound that is never tight — f(n) becomes insignificant compared to g(n) as n grows. To check if f(n) = o(g(n)), compute: limn→∞ f(n)/g(n). If this limit = 0, then f(n) = o(g(n)).

10.6 Little-omega (ω) Notation — Loose Lower Bound

Formal Definition

ω(g(n)) = { f(n) : for all positive constants c, there exists a positive constant n₀ such that 0 ≤ c·g(n) < f(n) for all n ≥ n₀ }

To check if f(n) = ω(g(n)), compute limn→∞ f(n)/g(n). If this limit = ∞, then f(n) = ω(g(n)).

10.9 Big-O Algebra (Combining Functions)

RuleStatement
Sum RuleIf f₁ = O(g₁) and f₂ = O(g₂), then f₁+f₂ = O(max(g₁,g₂)). In particular, if f₁ ≤ f₂ eventually, then f₁+f₂ = O(f₂).

✏️ Example using Sum Rule

27·log(n) + 19 + n = O(n), because the n term dominates 27·log(n)+19 for large n.

Exam-ready Answer: Difference between O, Ω and Θ

"Big-O notation gives the asymptotic upper bound on an algorithm's running time, representing the worst-case complexity. Big-Omega gives the asymptotic lower bound, representing the best-case complexity. Big-Theta gives a tight bound — it exists only when the upper bound (O) and lower bound (Ω) coincide asymptotically, representing the algorithm's exact/average growth rate. Formally, f(n)=Θ(g(n)) if and only if f(n)=O(g(n)) and f(n)=Ω(g(n))."

11. Worked Complexity Examples (Code → Big-O)

Below are representative code patterns you must be able to recognise instantly in an exam, with the reasoning behind each complexity.

① Single loop → O(n) 
for(i=1;i<=n;i++)
    printf("Himanshu");

The loop runs exactly n times → O(n) — linear time.

② Nested loop (both to n) → O(n²) 
for(i=1;i<=n;i++)
    for(j=1;j<=n;j++)
        printf("Himanshu");

Inner loop runs n times for each of the n outer iterations → n × n = O(n²) — quadratic time.

③ Dependent nested loop (triangular) → O(n²) 
for(i=1;i<=n;i++)
    for(j=1;j<=i;j++)
        for(k=1;k<=100;k++)
            printf("Himanshu");

Number of (i,j) pairs = 1+2+...+n = n(n+1)/2 ≈ O(n²). The innermost loop runs a constant 100 times (doesn't depend on n), so it doesn't change the order → total = O(n²).

④ Increment doubles each time → O(log₂n) 
for(i=1;i<=n;i=i*2)
    printf("Himanshu");

i takes values 1,2,4,8,...,2^k. Loop ends when 2^k > n ⟹ k ≈ log₂n. So it runs O(log₂n) times — logarithmic time. (Same logic applies to while(n>1){ n=n/2; } — each step halves n.)

⑤ Loop bound is a root → O(√n) 
for(i=1; i*i<=n; i++)
    printf("Himanshu");

The loop runs while i² ≤ n, i.e. until i ≈ √n → O(√n).

GATE-style variant: 

i=1; s=1;
while(s<=n){ i++; s=s+i; }
Here s after k steps ≈ sum 1..k ≈ k²/2. Setting k²/2 ≈ n gives k ≈ √(2n) → still O(√n).

⑥ Loop increases additively using outer index → O(n log n) 
for(i=1;i<=n;i++)
    for(j=1;j<=n;j=j+i)
        printf("Himanshu");

For a fixed i, inner loop runs about n/i times. Summing over all i: n/1+n/2+...+n/n = n·(1+1/2+...+1/n) = n·H(n) ≈ O(n log n) (harmonic series H(n) ≈ ln n).

⑦ Exponential growth → O(2ⁿ) 
for (i = 0; i < (1<

Loop runs 2ⁿ times → O(2ⁿ) — exponential time (very slow for even moderate n).

⑧ Recursive Factorial → O(n) 
int Factorial(int n){
    if (n==0) return 1;
    else return n * Factorial(n-1);
}

Makes exactly n recursive calls before hitting the base case → O(n) time, and O(n) space due to the recursion (call) stack.

⑨ Naive recursive Fibonacci → O(2ⁿ) 
int Fibonacci(int n){
    if (n==0 || n==1) return 1;
    return Fibonacci(n-1) + Fibonacci(n-2);
}

Each call branches into 2 more calls, forming a binary recursion tree of depth n → number of calls grows exponentially, exactly following the Fibonacci sequence's own growth, approximated as O(2ⁿ). (A classic example of why naive recursion can be disastrously slow — motivates dynamic programming, covered in later units.)

12. Searching Techniques

Searching means finding whether a particular value (called VAL) is present in a collection of data (e.g., an array) or not.

  • If the value is found → search is successful, and we return its position (index).
  • If the value is not found → search is unsuccessful, and an appropriate message is shown.

Two popular searching methods are studied in this unit: Linear Search and Binary Search. The right one to use depends entirely on how the data is organized (sorted or unsorted).

12.1 Linear Search (Sequential Search)

Concept

Linear Search is the simplest searching method. It compares the search value (VAL) with every element of the array, one by one, in sequence, until a match is found or the array ends. It is mostly used on an unordered (unsorted) list, since it makes no assumption about the order of data.

How it Works — Step by Step

  1. Start from the first element of the array.
  2. Compare the current element with VAL.
  3. If they match → search successful, return the position.
  4. If not, move to the next element and repeat.
  5. If the end of the array is reached without a match → search unsuccessful.

Algorithm (Pseudocode)

LINEAR_SEARCH(A, N, VAL)
Step 1: [INITIALIZE] SET POS = -1
Step 2: [INITIALIZE] SET I = 1
Step 3: Repeat Step 4 while I <= N
Step 4:     IF A[I] = VAL
                SET POS = I
                PRINT POS
                Go to Step 6
            [END OF IF]
            SET I = I + 1
        [END OF LOOP]
Step 5: IF POS = -1
            PRINT "VALUE IS NOT PRESENT IN THE ARRAY"
        [END OF IF]
Step 6: EXIT

Example & Dry Run

Array: A[] = {10, 8, 2, 7, 3, 4, 9, 1, 6, 5}, search VAL = 7 (0-indexed in C).

Check A[0]=10: 10 ≠ 7 → move on
Check A[1]=8: 8 ≠ 7 → move on
Check A[2]=2: 2 ≠ 7 → move on
Check A[3]=7: 7 = 7 → ✅ Match found! POS = 3

Result: Search successful, value found at index 3 (4 comparisons made).

Complexity Analysis

C Implementation

#include <stdio.h>
#define SIZE 20

int main() {
    int arr[SIZE], num, i, n, found = 0, pos = -1;

    printf("Enter the number of elements: ");
    scanf("%d", &n);

    printf("Enter the elements: ");
    for (i = 0; i < n; i++)
        scanf("%d", &arr[i]);

    printf("Enter the number to search: ");
    scanf("%d", &num);

    for (i = 0; i < n; i++) {
        if (arr[i] == num) {
            found = 1;
            pos = i;
            printf("%d found at position %d\n", num, i + 1); // +1 for 1-based display
            break;
        }
    }

    if (found == 0)
        printf("%d does not exist in the array\n", num);

    return 0;
}
Explanation of Key Parts of the Code
  • found flag tracks whether the element was located; initialised to 0 (false).
  • A single for loop scans the array sequentially from index 0 to n-1.
  • break exits the loop immediately once a match is found — this is what gives the best-case speed-up (we don't keep scanning after finding the value).
  • i + 1 is printed purely to show position in human-friendly 1-based form.

12.2 Binary Search

Concept

Binary Search is an efficient algorithm that works only on a sorted array. It finds the desired value using the minimum possible number of comparisons by repeatedly dividing the search space in half.

Dictionary Analogy

To find a word in a dictionary, you don't start from page 1. You open it roughly in the middle, compare the word there with your target word. If your word comes before it alphabetically, you search only the first half; otherwise you search the second half. You repeat this halving process until you find the word. This is exactly how binary search works.

How it Works — Step by Step

  1. Set BEG = first index, END = last index.
  2. Compute MID = (BEG + END) / 2.
  3. If A[MID] == VAL → found! Return MID.
  4. If A[MID] > VAL → the target must be in the left half; set END = MID - 1.
  5. If A[MID] < VAL → the target must be in the right half; set BEG = MID + 1.
  6. Repeat steps 2–5 while BEG ≤ END. If the loop ends without a match, the value is not present.

Algorithm (Pseudocode)

BINARY_SEARCH(A, lower_bound, upper_bound, VAL)
Step 1: [INITIALIZE] SET BEG = lower_bound
                      END = upper_bound, POS = -1
Step 2: Repeat Steps 3 and 4 while BEG <= END
Step 3:     SET MID = (BEG + END)/2
Step 4:     IF A[MID] = VAL
                SET POS = MID
                PRINT POS
                Go to Step 6
            ELSE IF A[MID] > VAL
                SET END = MID - 1
            ELSE
                SET BEG = MID + 1
            [END OF IF]
        [END OF LOOP]
Step 5: IF POS = -1
            PRINT "VALUE IS NOT PRESENT IN THE ARRAY"
        [END OF IF]
Step 6: EXIT

Example & Dry Run (Successful Search)

Sorted Array (0-indexed): A[] = {3, 8, 15, 21, 29, 41, 50, 63, 72, 88}, n=10, search VAL = 41

Step 1: BEG=0, END=9 → MID=(0+9)/2=4 → A[4]=29. 29 < 41 → search right half → BEG=5
Step 2: BEG=5, END=9 → MID=(5+9)/2=7 → A[7]=63. 63 > 41 → search left half → END=6
Step 3: BEG=5, END=6 → MID=(5+6)/2=5 → A[5]=41. ✅ Match! POS=5

Result: Found in only 3 comparisons, versus up to 10 for linear search on the same data!

Complexity Analysis

With each comparison, the segment to be searched is halved. If it takes f(n) comparisons to search an array of size n, then: 2f(n) ≥ n, which gives us f(n) = log₂n.

CaseComplexity
Best CaseO(1) — target is exactly the middle element on first try
Worst CaseO(log₂n)
Average CaseO(log₂n)

Space Complexity: O(1) for the iterative version; O(log n) for the recursive version due to the recursion call stack.

Important Pre-condition

Binary Search requires the array to be sorted beforehand. If the data is not sorted, you must sort it first (adding an extra O(n log n) sorting cost) — a classic example of time–space/time–time trade-off when deciding whether binary search is worth it for a one-time search vs. repeated searches.

C Implementation (Iterative)

#include <stdio.h>
#define SIZE 10

int main() {
    int arr[SIZE], num, i, n, beg, end, mid, found = 0;

    printf("Enter the number of elements: ");
    scanf("%d", &n);

    printf("Enter the SORTED elements: ");
    for (i = 0; i < n; i++)
        scanf("%d", &arr[i]);

    printf("Enter the number to search: ");
    scanf("%d", &num);

    beg = 0; end = n - 1;
    while (beg <= end) {
        mid = (beg + end) / 2;
        if (arr[mid] == num) {
            printf("%d found at position %d\n", num, mid + 1);
            found = 1;
            break;
        }
        else if (arr[mid] > num)
            end = mid - 1;
        else
            beg = mid + 1;
    }

    if (!found)
        printf("%d does not exist in the array\n", num);

    return 0;
}
Alternate Implementation — Recursive Binary Search (same algorithm, recursive style)

This is the exact same algorithm/logic as above, just expressed using recursion instead of a while loop — a common alternate coding style asked in exams:

int binarySearchRec(int arr[], int beg, int end, int val) {
    if (beg > end) return -1;          // base case: not found
    int mid = (beg + end) / 2;
    if (arr[mid] == val) return mid;   // found
    else if (arr[mid] > val)
        return binarySearchRec(arr, beg, mid - 1, val);  // search left half
    else
        return binarySearchRec(arr, mid + 1, end, val);  // search right half
}

Time complexity remains O(log n); space complexity becomes O(log n) due to the recursive call stack (each call adds one frame, and there are log n calls in the worst case).

Explanation of Key Parts of the Code
  • The array must be sorted before applying binary search — this is the single most important pre-condition.
  • mid = (beg+end)/2 always points to the middle of the current search range.
  • Depending on comparison with arr[mid], either beg or end is updated to shrink the search range by half each time.
  • Loop terminates when beg > end — meaning the search range has become empty.

Revise: Data & Data Structures
  • Data type = domain of values + set of operations.
  • Simple/atomic types have no components; structured types can be broken into fields.
  • Data structure = organized way of storing data + operations permitted on it.
  • Classified as Linear (Array, Stack, Queue, Linked List) vs Non-Linear (Tree, Graph, Heap, Hash Table).
  • Also classified as Homogeneous (Array) vs Non-Homogeneous (Structure, Class).
Revise: ADT
  • ADT = mathematical model + operations, with implementation hidden.
  • Specification (what) is separate from Implementation (how).
  • Users only need the specification; implementers need everything.
Revise: Algorithm & Analysis
  • Algorithm = finite, unambiguous, effective sequence of steps with input/output.
  • Characteristics: Input, Output, Definiteness, Finiteness, Effectiveness, Generality, Independence, Optimality.
  • Time complexity = running time as function of n; Space complexity = memory as function of n.
  • Best/Worst/Average case; Worst case gives an upper-bound guarantee, most commonly used.
Revise: Time–Space Trade-off
  • Increasing memory can reduce time, and vice versa.
  • Choice depends on available memory, speed needs, frequency of operation, hardware.
  • Example: hash table (more memory, O(1) avg search) vs linear search (less memory, O(n) search).
Revise: Asymptotic Notations
  • O = upper bound (worst case); Ω = lower bound (best case); Θ = tight bound.
  • o and ω are strict (non-tight) versions of O and Ω respectively.
  • f(n)=Θ(g(n)) iff f(n)=O(g(n)) AND f(n)=Ω(g(n)).
  • Use limits: lim f/g = 0 → o; finite constant → Θ; ∞ → ω.
Revise: Searching
  • Linear Search: sequential comparison, works on unsorted data, O(n) worst case.
  • Binary Search: needs sorted data, halves search space each time, O(log n) worst case.
  • Binary search formula: number of comparisons f(n) satisfies 2^f(n) ≥ n ⟹ f(n)=log₂n.

15. Complete Unit Summary

Unit 1 lays the groundwork of DSA in three big pieces:

Part A — Foundations

Data is organized into data types and data structures. Structures may be linear (Array, Stack, Queue, Linked List) or non-linear (Tree, Graph, Heap, Hash Table), and homogeneous (Array) or non-homogeneous (Structure/Class). An Abstract Data Type (ADT) separates what a structure does (specification) from how it's built (implementation). Standard operations on any structure: Traversal, Insertion, Deletion, Searching, Sorting, Merging.

Part B — Measuring Efficiency

An algorithm is a finite, unambiguous sequence of steps. We measure its efficiency using time complexity and space complexity, evaluated in best, worst (most common), and average cases. The Time–Space Trade-off reminds us that saving time often costs memory, and vice versa. Asymptotic notations (O, Ω, Θ, o, ω) let us describe growth rate cleanly, ignoring constants — O=worst-case upper bound, Ω=best-case lower bound, Θ=tight bound.

Part C — Applying It: Searching

Linear Search checks elements one by one — simple, works on unsorted data, O(n) worst case. Binary Search repeatedly halves a sorted array to find a value in O(log n) — dramatically faster for large datasets, but requires the pre-condition that the data is sorted. Together, these two algorithms are the simplest real demonstration of how asymptotic analysis and algorithm design directly translate into performance differences.

18. Important Practice Questions

A. Definition-based

Q1. Define Data Structure. What are its types?

A data structure is a way of organizing data in memory so it can be used efficiently, along with the set of operations permitted on it. Types: Linear (Array, Stack, Queue, Linked List) and Non-Linear (Tree, Graph, Hash Table, Heap); also classified as Homogeneous (Array) and Non-Homogeneous (Structure/Class).

Q2. What is an Abstract Data Type? Give an example.

An ADT is a mathematical model of a data type defined only by its allowed values and operations, with implementation details hidden. Example: A Stack ADT defines push(), pop(), peek(), isEmpty() without specifying array or linked-list implementation.

Q3. List the characteristics of a good algorithm.

Input, Output, Definiteness (unambiguous), Finiteness, Effectiveness/Feasibility, Generality, Independence from language, and (desirably) Optimality.

B. Difference / Comparison Questions

Q4. Differentiate between Linear and Non-Linear data structures.

Linear: elements arranged sequentially, traversed in a single run, easy to implement (Array, Stack, Queue, Linked List). Non-Linear: elements can connect to multiple other elements, support multi-level storage, harder to implement but more memory-efficient (Tree, Graph).

Q5. Differentiate Big-O, Big-Omega and Big-Theta notations.

O = asymptotic upper bound (worst case); Ω = asymptotic lower bound (best case); Θ = tight bound that holds only when O and Ω bounds coincide (average/exact growth). See Section 10.7 table for the full comparison.

Q6. Differentiate Linear Search and Binary Search.

See the comparison table in Section 13.1 — key difference: Linear search needs no sorted order and is O(n); Binary search needs sorted data and is O(log n).

Q7. Differentiate best case, worst case and average case complexity.

Best case = minimum possible running time (input is most favourable). Worst case = maximum possible running time over all inputs of size n (gives a guarantee, most commonly analysed). Average case = expected running time averaged over all inputs (requires probability distribution of inputs).

C. Algorithm / Dry-run Questions

Q8. Write the algorithm for Linear Search and trace it for A[]={5,3,8,1,9}, VAL=1.

See Section 12.1 for pseudocode. Trace: compare 5≠1, 3≠1, 8≠1, 1=1 → found at index 3 (0-indexed) after 4 comparisons.

Q9. Write the algorithm for Binary Search and trace it for A[]={2,4,6,8,10,12,14}, VAL=10.

n=7, indices 0–6. BEG=0,END=6,MID=3→A[3]=8<10→BEG=4. BEG=4,END=6,MID=5→A[5]=12>10→END=4. BEG=4,END=4,MID=4→A[4]=10 → found at index 4 in 3 comparisons.

Q10. Prove that 3n² + 5n + 2 = O(n²).

Need c, n₀ such that 3n²+5n+2 ≤ c·n² for n≥n₀. For n≥1: 5n≤5n² and 2≤2n², so 3n²+5n+2 ≤ 3n²+5n²+2n² = 10n². Take c=10, n₀=1. Hence proved, 3n²+5n+2 = O(n²).

Linear Search: Time O(n) worst/avg, O(1) best; Space O(1). Binary Search: Time O(log n) worst/avg, O(1) best; Space O(1) iterative / O(log n) recursive.
